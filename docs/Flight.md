# 现场运行与耳机恢复

尚未完成整段实机验收。先证明基础能力，再组合任务；使用护桨与符合现场要求的受控区域，由现场人员保有停止/降落能力。环境与凭据见 [Setup](Setup.md)。

## 启动前与地面检查

1. 只开一架 Tello，检查电池、护桨、地面纹理、光照和通道；电脑同时联网，不与其他程序或手机 App 争用飞机。
2. 确认火山 RTC、豆包语音与方舟服务、费用和凭据，并在 RTC 控制台核对 RTS 高级消息容量，安装依赖并完成 [离线与容器检查](Testing.md)。
3. 用 `.\start_flight.ps1 -DryRun` 预览参数和配置路径；它不验证配置。核对佩戴标记与跟随配置；速度上限采用 RC 单位，变化率采用 RC/秒，不再使用 0..1 比例。不给帐篷附标记掩盖视觉能力缺失。
4. 先不授权起飞，运行 `.\start_flight.ps1`。Python 预检通过不等于云、耳机或飞机已验证。
5. 手动打开启动器打印的地址，默认 http://127.0.0.1:18848；明确选择麦克风和耳机再连接。换电脑或蓝牙重连后重新选择；会话重启后刷新网页取得新授权。

页面必须显示真实 SDK 无人机图像，不能是电脑摄像头或静态图。核对遥测、解码身份与时间，并另测真实画面延迟；解码时间不是相机曝光时间。

先实际听见回复，再让模型复述本次新说的话。随后用短动作核对新工具接管会停止旧程序、迟到旧工具被拒绝；普通对话不取消正在执行的程序。地面阶段确认热键可用，但不据此推断空中刹停性能。

## 媒体暂缺与恢复

在麦克风、耳机、播放或图像暂缺时暂停相应媒体，保留控制会话与文字状态；不会自动改用电脑麦克风/扬声器或重放丢弃的旧音频。图像过期仍会阻止依赖视觉的动作，保留会话不代表画面有效。

恢复原来选择的设备后，点击“恢复所选设备音频”。图像恢复后须取得新的有效帧；重复帧不刷新时效。若提示音频处理器不可恢复或真正连接失败，先停止、核对飞机状态，再重启入口；不要把媒体暂停与会话断开混为一谈。此恢复流程的软件回归不能替代真实蓝牙测试。

蓝牙开麦可能切换通话音质；驱动、回声、无人机噪声和设备断开需现场测量。收到云字节不证明耳机发声。紧急停止用操作员热键，不等模型听清或生成工具。

## 分阶段飞行

现场具备条件后重新启动并授权：

```powershell
.\start_flight.ps1 -AllowTakeoff
```

1. 低高度、短位移分别核对起飞、方向、停止和降落。
2. 再开始跟随并短距离走动，逐轴检查自适应横移/偏航、上下方向、高度时效与边界保护。标记丢失、帧过期或图传间隔异常时应归零等待，新鲜稳定目标回来后恢复；显式停止后不能自动恢复。
3. 分别验证画面问答和短动作，再尝试组合任务。依据真实飞机、录像和工具结果判断，模型说“完成”不算通过；accepted 不是动作完成。
4. 红帐篷导航、到达、避障和转身找回用户未通过实机验证。失败应保持停止并说明原因，不能用静态图片或固定动作制造通过记录。

Ctrl+Shift+Alt+A / F12 停止；Ctrl+Shift+Alt+L / F11 降落。热键独立于云端；详细取消和命令通道歧义见 [Architecture](Architecture.md)。

## 结束与留证

挂断后核对真实落地、图传、常驻容器和云会话关闭。程序退出默认请求降落；未确认落地或云任务停止时，现场人员继续处理，退出进程不算完成。显式 `-ExitAction hover` 不要求落地，仍需确认停止与资源清理。

应用与跟随事件共用 `logs/Runtime`，复制前等待写入关闭/flush。日志约 16 MB 分段，共享默认十进制 1 GB 保留预算，旧的已关闭分段会回收，需要的证据及时另存；活动/旧格式日志不会自动删除，预算或磁盘失败记录在日志器状态，可能丢失部分日志，但不中断飞行任务。迁移前 `follow/logs` 属历史记录。日志不保存原图/音频，现场视频另录；凭据、现场媒体和运行日志不随源码上传。
