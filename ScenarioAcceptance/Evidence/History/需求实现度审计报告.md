### 0.3 独立复现实验：Gateway 允许“无观察/不可见目标”直接运动

我对 `Gateway` 做了一个不连硬件的离线探针（假的 real backend，`simulated=False`）：

```text
move_without_observation: {'ok': True, 'status': 'completed', ...}
calls: [('move_forward', (50,))]

move_after_invisible_observation: {'ok': True, 'status': 'completed', ...}
calls2: [('move_forward', (50,))]
```

这说明：**即使从头到尾没有调用 `observe()`，或者视觉模型明确返回 `visible=false`，Gateway 仍会向真实后端下发 `move_forward`。** 这是本次审计发现的最高优先级逻辑漏洞，详见第 3 节。

## 2. 存在风险或部分实现的需求

### 2.1 物理定高/悬停：代码只能“假设”固件能力，不能证明

- 需求原文把“定高、稳定悬停”写成“在预定演示环境中保持足够稳定的位置和高度”。
- 代码没有高度闭环 PID，也没有外部定位；`_driver._current_height()` 主要读 Tello `get_height()`，上升/下降时再用指令量估算高度。
- `MAX_HEIGHT_CM=250` 是软件上限，不是对真实悬停漂移的保证。
- `FollowService` 文件头明确写着：`this service cannot interrupt a blocking backend or prove physical hovering`（[service.py](modules/follow/r3_follow/service.py:4)）。
- 结论：**硬件能力项，代码层只能算“准备了接口”，没有验收证据。**

### 2.2 跟随的物理调参与距离语义不完整

- `FollowController` 用“画面中标记的平均边长 / 图像宽度”作为参考尺寸，不是米制距离；代码注释也明确 `not an experimentally measured yaw speed`、`physical_tuning_verified: False`（[core.py](modules/follow/r3_follow/core.py)）。
- 侧视/透视时 `ApparentSizeGuard` 会阻止前后运动，这是安全设计，但也意味着**转身时跟随会停前后、只转向/平移**；真实效果未验证。
- 跟随输出被 clamp 到左右/前后 ±30、yaw ±20（[service.py](modules/follow/r3_follow/service.py) `control_once()`），这是“预览比例”，不是实测速度。
- 没有测距、避障、地理围栏；只能靠目视和安全员。
- 结论：**短距离跟随的算法闭环有，物理可用性未达标。**

### 2.3 双网连接只在文档里，没有运行时防呆

- [FLIGHT_SOP.md](FLIGHT_SOP.md) §3 要求手动 `ping 192.168.10.1`、`curl https://api.deepseek.com`、`route print 0.0.0.0`，并手动降低 Tello 网卡默认路由优先级。
- 代码侧只有 `run_auto_integration.py` 检查 UDP 8889 是否被占用（[run_auto_integration.py](run_auto_integration.py:244)），没有检查：
  - 当前默认路由是否走手机网卡；
  - Tello Wi-Fi 是否抢走默认路由；
  - 云端 API 是否可达；
  - 两个网卡是否同时在线。
- 更严重的是：SOP 写“外网不通会退化为 Mock 回复”，但 `main.py` 在 `--live` 下创建的是 `ModelClient()`，网络失败会直接抛错，**不会自动回退到 ScriptedClient**（[main.py](modules/ai/main.py) 的 `client = ModelClient() if args.live else ScriptedClient()`）。
- 结论：**双网是“人工 SOP”，不是代码能力；现场若无外网，语音问答会直接失败，不是自动降级。**

### 2.4 实时语音延迟没有验收指标，且依赖 Docker/兼容端点

- `--always-on` 是串行链路：VAD 静音 1.5s 判停 + STT + LLM + TTS；播报期间还会关闭麦克风（`listen_pause`），本质是“对讲机”，不是全双工。
- `--realtime` 是全双工路线，但：
  - 只记录 `speech_end_to_first_audio_ms`（[realtime.py](modules/ai/realtime.py:161)），没有阈值、没有报告、没有端到端（含工具执行/TTS 输出）测量；
  - `RealtimeSession.run()` 启动前会 `await self.runner.check()`（[realtime.py](modules/ai/realtime.py:207)），而 `SandboxRunner.check()` 要求 Docker；**没有 Docker 时 `--realtime` 直接启动失败**，即使只想语音对话；
  - 需要 `AI_REALTIME_URL/AI_REALTIME_API_KEY/AI_REALTIME_MODEL`，且必须是兼容该 WebSocket 协议的端点；仓库没有真实端点验收证据；
  - 没有 AEC；`DuplexAudio` 只请求服务端 `near_field` 降噪，文档也承认“近讲降噪不等于回声消除”。
- 结论：**“实时”仍是体验目标，不是已实现指标。**

### 2.5 旧帧处理是“路径内有效”，不是全局保证

已实现的部分：
- `FollowService.capture_once()` 拒绝 `stale`、`frame is None`、`age > 0.5s`（[service.py](modules/follow/r3_follow/service.py:159)）；
- `Vision.frame()` 拒绝 `stale`/空帧/`age > 0.5s`（[vision.py](modules/ai/vision.py:24)）；
- `Vision.observe()` 在推理后再次检查 `0.5s`（[vision.py](modules/ai/vision.py:41)）；
- `FollowController.observe()` 拒绝倒退/重复 `frame_id`；`Gateway` 对 `sdk_camera` 的重复 `(source, frame_id)` 拒绝。

但全局不成立：
- `Gateway.dispatch()` 只有在 `self.observation is not None` 时才检查画面来源和时效（[gateway.py](modules/ai/gateway.py:97)）。**不调用 `observe()` 就没有任何时效检查。**
- `visible=false` 的观察也会被保存为 `self.observation`；后续移动只检查来源/时间，不检查 `visible`，所以**“没看到目标”仍可移动**。
- 单调用 legacy 路径完全绕过 Gateway（见 2.7）。
- `FrameBridge` 使用的是“解码线程得到帧的本地时间”，不是无人机曝光/采集时间；0.5s 在步行速度下可能对应几十厘米位移。
- 结论：**旧帧防线存在，但可被“不观察/观察失败/legacy 路径”绕过。**

### 2.6 “急停/降落接口 50ms 返回”不等于“物理停止/物理降落”

- `test_concurrency.py` 证明了 `stop_motion()`/`land()` **接口**在阻塞动作进行中 50ms 内返回，但它没有证明飞机真的停下/落地。
- `_driver.interrupt('land')` 先发 RC 零速，再把 `tello.land()` 交给后台线程；后台线程还要抢 `_command_lock`，而正在执行的 `move_forward` 可能还占着锁。
- `API.md` 写“底层会强行打断当前动作”，但 `service.py` 自己的注释是“cannot interrupt a blocking backend”；两处表述不一致。
- `stop_motion` 只表示“零速度请求已发送”，`ai_bridge.stop_motion()` 也明确返回 `motion_stopped_confirmed=False`（[ai_bridge.py](drone_sdk/ai_bridge.py:166)）。
- 结论：**接口实时性达标，物理实时性未证明；现场必须保留人工物理急停/安全员。**

### 2.7 模型单调用 legacy 路径绕过 Docker 和视觉检查

- `Runner.run()` 判断：如果代码是单条 `drone.<COMMANDS>()` 调用，就走 `Demo.handle()`（宿主进程），而不是 `run_sandbox()`（[program_runner.py](modules/ai/program_runner.py:72)）。
- `Demo.handle()` 直接调用 `UnifiedDrone`，没有 Gateway 的“必须新鲜观察”检查（[demo_text.py](modules/ai/demo_text.py)）。
- 该路径仍有 `program_runner.validate()` 白名单（只允许单个调用、参数受限），所以不是任意代码执行；但它**没有容器隔离，也没有视觉时效门禁**。
- 这与 `REVIEW_FIXES.md` 中“generated programs execute exclusively inside Docker”的表述不一致：至少单调用路径不是。
- 结论：**“模型代码必须进沙箱”的边界只对多语句/非 legacy 代码成立；单调用路径是旁路。**

### 2.8 真实跟随仍使用“声明为 simulation-only”的端口

- `Team2StubPort.simulation_only = True`（[team2_adapter.py](modules/follow/r3_follow/team2_adapter.py:71)）。
- `FollowService` 只接受 `simulation_only is True` 的端口（[service.py](modules/follow/r3_follow/service.py:29)），并在日志里固定写 `simulation_only=True, hardware_verified=False`（[service.py](modules/follow/r3_follow/service.py:74)）。
- 但 `main.py --real-drone` 仍可通过 `controller.start_follow()` 走到这个端口，最终调用真实 `_driver.set_velocity`。
- 也就是说：**代码一边声明“仿真端口、未做硬件验证”，一边允许真实起飞后的跟随控制。** 这不是“完全不能飞”，而是“安全标签与真实能力不一致”，非常容易让现场误判。
- 另外，`FollowCore` 明确 `physical_tuning_verified: False`，真实 yaw 方向未验证。

### 2.9 `Gateway.start_follow()` 忽略释放控制权失败

- 代码：
  ```python
  if self.acquired:
      await asyncio.to_thread(self.backend.release_control,'model'); self.acquired=False
  return await asyncio.to_thread(self.backend.start_follow)
  ```
  （[gateway.py](modules/ai/gateway.py:79)）
- 它不检查 `release_control` 的返回值，也不看失败原因；如果释放因为 `action_result_pending` 失败，`self.acquired` 已被置 False，后续 `finish()` 不会再尝试释放/停止。
- 结论：**存在控制权泄漏和“动作残留”风险。**

### 2.10 其他中低风险

- `Ai Agent` 的固定提示词仍写“你是无人机模拟演示助手”“全部设备结果均为模拟”（[ai_agent.py](modules/ai/ai_agent.py:4/14)），在真机模式下会误导模型/播报。
- `Agent.handle()` 只用关键词拦截否定（`不要/禁止/别起飞/不许/do not/don't`），不是通用意图校验；实时 Realtime 路径没有这层关键词兜底。
- `takeoff` 一旦用 `--allow-real-takeoff` 授权，任何模型生成的 `drone.takeoff()` 都可以起飞；没有“每次起飞二次确认”或“双人确认”。
- `Gateway` 允许 20–500cm 的移动；`realtime.INSTRUCTIONS` 也明确告诉模型“20 至 500”。室内 5m 单步移动偏大；没有地理围栏。
- `update_velocity` 没有“必须有观察”的要求，也没有最长持续时间限制；程序中循环调用可让飞机持续运动到 90s 超时。
- `_driver.health()` 里 `get_battery()`/`get_height()` 没有 deadline 包装（[\_driver.py](drone_sdk/_driver.py:312)），链路卡住时可能拖慢状态查询。
- `API.md` 仍有一句“controller.get_status() 仍上报 simulated=True”，与当前代码“读取 `_driver.SIMULATED`”不一致；文档需要同步。

## 3. 未实现/代码中找不到证据的需求

### 3.1 “真的拦住模型的越权指令了吗？”——**没有完全拦住**

**已做的：**
- 模型只能调用 `run_program`/`interrupt` 两个工具；代码在 Docker 中执行；宿主 RPC 有白名单和参数校验；起飞有授权/电量门禁；速度/高度有硬限制。

**没有做到的（P0）：**
1. **无观察也能移动**：`Gateway.dispatch()` 只在 `self.observation is not None` 时检查画面（[gateway.py](modules/ai/gateway.py:97)）。我的离线探针已证明 `move_forward(50)` 在从未 `observe()` 的情况下返回成功。
2. **目标不可见也能移动**：`visible=false` 的观察被保存后，移动只检查来源/时间，不检查 `visible`；探针同样证明 `visible=false` 后仍下发 `move_forward(50)`。
3. **legacy 单调用绕过 Gateway**：模型生成 `drone.move_forward(30)` 这类单调用时，走宿主 `Demo.handle()`，没有视觉时效门禁（[program_runner.py](modules/ai/program_runner.py:72)）。
4. **没有地理围栏/避障/测距**：`DISTANCE` 允许 20–500cm；`update_velocity` 允许 ±100；没有基于画面或传感器的安全边界。
5. **没有逐命令人工确认**：`--allow-real-takeoff` 是全局开关，不是每次动作确认；模型一旦获得控制权，可在授权范围内连续动作。

**结论：** 代码有“白名单 + 沙箱 + 控制权 + 硬限制”的多层防线，但**“模型不能盲飞”这条最关键的边界没有实现**。如果团队明确允许“开环短动作”，也必须用独立开关把它限制为短距离 + 人工确认；当前代码没有这种区分。在真机自主导航语境下，这是可导致撞人/撞物的致命逻辑漏洞。

### 3.2 “旧画面处理了吗？”——**部分处理，未形成全局保证**

- 已实现：`FollowService` 0.5s 时效、`Vision.frame/observe` 0.5s 前后复查、`FollowController` 拒绝重复/倒退帧、`Gateway` 拒绝重复 `(source, frame_id)`。
- 未实现/可绕过：
  - 不调用 `observe()` 直接移动（3.1）。
  - `visible=false` 仍可移动（3.1）。
  - legacy 单调用路径不经 Gateway（2.7）。
  - `controller.get_frame()` 自身允许 1.0s（[controller.py](drone_sdk/controller.py:76)），与 follow/vision 的 0.5s 不一致；直接调用 SDK 的调用方可能拿到更旧画面。
  - `FrameBridge` 用解码本地时间而非无人机采集时间；0.5s 只是“解码后到使用”的年龄，不是“曝光到使用”的年龄。
- **结论：** “旧帧防线”在跟随/视觉代码里是有的，但不能说“所有运动都不会使用旧画面”。

### 3.3 “双网冲突代码有防呆吗？”——**没有**

- 只有 [FLIGHT_SOP.md](FLIGHT_SOP.md) §3 的人工检查清单：`ping`、`curl`、`route print`。
- 只有 [run_auto_integration.py](run_auto_integration.py:244) 检查 UDP 8889 占用，不是双网检查。
- 没有：
  - 绑定 Tello 网卡或指定源地址；
  - 检查默认路由 metric；
  - 检查外网/云端 API 连通性；
  - 检测 Tello Wi-Fi 抢默认路由；
  - 断网时自动回退到固定指令/Mock；
  - 双网切换后的重连。
- **结论：** 现场必须人工按 SOP 做；代码没有防呆，也没有自动降级。

### 3.4 “模型口头回答‘已执行’能当证明吗？”——**不能，代码也没有物理证明**

- 代码确实返回了真实工具结果/journal：`SandboxRunner` 的 `journal`、`Gateway` 的 `ok/status`、`UnifiedDrone` 的 `status/message`；`SandboxRunner` 还会把有 RPC 错误的程序判为失败（[sandbox_runner.py](modules/ai/sandbox_runner.py:38)）。
- 但：
  - `stop_motion`/`land` 的返回值只是“请求已发送”，不是物理完成（[ai_bridge.py](drone_sdk/ai_bridge.py:166)）；
  - `FollowService` 明确不能证明物理悬停（[service.py](modules/follow/r3_follow/service.py:4)）；
  - 没有独立的高度/位置/电机状态传感器；
  - `land` 有“等待落地状态”屏障，但这只是 SDK 状态，不是外部测量。
- **结论：** “模型不能仅凭嘴说完成”在提示词和返回值层面做了约束，但“物理完成”仍无独立证据；现场需要人工目视确认。

### 3.5 “实时语音延迟”有数据吗？——**没有验收数据**

- 只有 `speech_end_to_first_audio_ms` 日志（[realtime.py](modules/ai/realtime.py:161)），没有门限、没有报告、没有“说完到听见”的端到端测量。
- `--always-on` 还有 1.5s 静音判停 + STT/LLM/TTS 串行；`listen_pause` 在播报期间关闭麦克风，不是全双工。
- 没有真实耳机、电机噪声、AEC 测试；`HEADSET_TEST.md` 也明确说“近场降噪不等于 AEC”“本轮音频验证使用内置模拟设备”。
- **结论：** “实时”目前是体验目标，不是已实现性能指标。

### 3.6 “遮挡/转身/找回用户”有真实验证吗？——**只有合成图/离线测试**

- 仓库有大量合成图测试：`test_side_turn_guard.py`、`test_yaw_follow.py`、`test_service.py`、`test_long_recovery.py` 等，覆盖侧视、形状歧义、短暂丢失、恢复窗口。
- 但没有真实无人机视频、真实人体标记、真实转身/遮挡的录制与回放验收。
- 跟随 3s 恢复窗口超时后进入 `target_lost` 并锁存，必须显式重启；**没有“飞离画面后自动找回用户”**（[REVIEW_FIXES.md](REVIEW_FIXES.md) 也把它列为未供能力）。
- **结论：** 算法行为在合成场景下通过，真实场景未验收；“自动找回”未实现。

### 3.7 “云端模型控制飞机”有真实链路证据吗？——**没有**

- 代码有 `ModelClient`（HTTPS、无重定向）、`Vision.observe`、`RealtimeSession`、`SandboxRunner`，但仓库没有真实模型/账号/兼容端点的验收记录。
- `--realtime` 需要独立的 `AI_REALTIME_URL`，且启动前要求 Docker；本机两者都没有。
- `main.py --always-on` 可用本地 whisper，但 LLM/TTS 仍需配置；本机自检显示 `LLM=False, TTS=False`。
- **结论：** 代码路径存在，真实云端链路未验收；现场必须提前用实际 Key 和端点跑通。

### 3.8 Docker 沙箱有真实执行证据吗？——**没有**

- 本机 `docker` 命令不存在，`companion-sandbox:0.4` 镜像不存在。
- `ScenarioAcceptance/README.md` 也写明 3 个 Docker 集成测试未运行；T06–T08 只验证“程序准入”，不执行容器。
- `--realtime` 和任何多语句模型程序都会在 `runner.check()` 处失败；只有 legacy 单调用路径能在无 Docker 时工作。
- **结论：** “完整 Python 程序在容器中执行”是设计，不是本机已验证能力；黑客松现场若没有 Docker，模型多步程序会不可用。

### 3.9 “预算 ≤1000 元”有代码证据吗？——**没有**

- 这是项目管理/采购要求，代码库没有费用记录、租赁状态、云端调用计费或预算守卫。
- 只有 `README`/`FLIGHT_SOP` 的文字说明；不能由代码审计证明满足预算。

## 4. 终极结论

### 4.1 分场景结论

| 场景 | 结论 | 理由 |
|---|---|---|
| **纯离线/模拟演示** | **可以支撑** | `ScriptedClient + MockDrone`、43 项场景、34 项矩阵、语音自检、并发/急停全绿；不依赖硬件/云/Docker |
| **真机 + 人工安全员的受控演示** | **有条件可以** | 起飞门禁、限速/限高、控制权/代次、急停接口都在；但必须人工双网检查、物理急停、限制模型动作、预先跑地面测试 |
| **真机 + 云端模型自主控制/无人值守** | **不可以** | 存在“无观察/不可见目标也能移动”的 P0 盲飞漏洞；legacy 单调用绕过视觉门禁；真实跟随仍标 simulation-only；双网无防呆；物理停止未证明 |

### 4.2 致命/高风险逻辑漏洞清单

| 级别 | 漏洞 | 代码位置 | 后果 |
|---|---|---|---|
| **P0** | 无观察也能移动 | [gateway.py](modules/ai/gateway.py:97) 的 `and self.observation is not None` | 模型/程序可盲飞；离线探针已复现 |
| **P0** | `visible=false` 仍能移动 | 同上，未检查 `o.get('visible')` | 视觉明确说“没看到”仍会前进 |
| **P0** | 单调用 legacy 路径绕过 Docker + Gateway 视觉门禁 | [program_runner.py](modules/ai/program_runner.py:72)、[demo_text.py](modules/ai/demo_text.py) | 模型可生成单调用直接驱动机器，绕过沙箱/时效 |
| **P1** | 真实跟随使用 simulation-only 端口 | [team2_adapter.py](modules/follow/r3_follow/team2_adapter.py:71)、[service.py](modules/follow/r3_follow/service.py:29/74) | 安全标签与真实能力不一致；未验证 yaw/物理参数 |
| **P1** | `start_follow` 忽略释放控制权失败 | [gateway.py](modules/ai/gateway.py:79) | 控制权泄漏/残留动作 |
| **P1** | 双网无运行时防呆、无自动降级 | [FLIGHT_SOP.md](FLIGHT_SOP.md:48)、[run_auto_integration.py](run_auto_integration.py:244) | 现场外网/路由失败即语音失败；SOP 的“Mock 降级”未在代码实现 |
| **P1** | 阻塞动作无法保证物理打断 | [\_driver.py](drone_sdk/_driver.py:273/282)、[service.py](modules/follow/r3_follow/service.py:4) | 急停接口 50ms 返回，但飞机可能继续完成 `move_forward` |
| **P1** | `--realtime` 启动强依赖 Docker | [realtime.py](modules/ai/realtime.py:207)、[sandbox_runner.py](modules/ai/sandbox_runner.py:12/19) | 没有 Docker 时全双工语音不可用；本机已确认无 Docker |
| **P2** | 实时延迟无门限/无端到端测量 | [realtime.py](modules/ai/realtime.py:161) | 无法证明满足“实时”体验 |
| **P2** | 500cm 单步/无地理围栏/无避障 | [gateway.py](modules/ai/gateway.py:83)、[realtime.py](modules/ai/realtime.py:20) | 室内模型动作可能过大 |
| **P2** | 真机模式提示词仍说“全部模拟” | [ai_agent.py](modules/ai/ai_agent.py:4/14) | 模型/播报可能误报环境 |

### 4.3 现场演示的最低建议（按优先级）

1. **先修 P0**：在 `Gateway.dispatch()` 中要求所有真实运动必须有**新鲜、`visible=true`** 的 `sdk_camera` 观察；禁止“无观察移动”；把 legacy 单调用也送进同一检查。
2. **修控制权释放**：`start_follow()` 必须检查 `release_control` 的 `ok`，失败即中止，不能把 `acquired` 置 False。
3. **双网预检做成代码**：启动前检查 Tello `ping`、云端 HTTPS、默认路由/网卡；不满足就拒绝进入真机模式；`--live` 失败要有明确降级或固定指令模式。
4. **真机跟随要么禁用，要么先做真实标定**：至少验证 yaw 方向、速度尺度、标记遮挡/转身；在日志和 UI 上明确 `hardware_verified`，不要把 simulation-only 端口用于真实飞行。
5. **Docker 预检**：现场若要 `--realtime` 或多步程序，提前构建 `companion-sandbox:0.4` 并跑通一条 `--program`；否则改用 `--always-on` + 单调用白名单。
6. **保留人工物理急停/安全员**：`stop_motion`/`land` 是“请求已发送”，不是“已停止/已落地”；不要在演示中把返回 `ok` 当作物理完成。
7. **预跑真机地面测试**：`run_ground_test.py --props-removed`、`run_final_real_sim.py --props-removed`、`test_voice_loop.py`，并录制真实画面/日志。
8. **限制室内动作**：把模型可用移动距离临时降到 30–50cm，禁用 500cm；飞行区域加围栏/保护罩。

### 4.4 一句话结论

**这套代码的“离线/模拟闭环”完成度很高，可以支撑黑客松的受控演示；但“真机 + 云端模型自主控制”尚未达到可现场放飞的标准——最致命的是 Gateway 允许在“从未观察”或“视觉明确不可见”时直接移动，其次是 legacy 单调用绕过视觉门禁、真实跟随未做硬件验证、双网无代码防呆、阻塞动作无法保证物理打断。现场演示必须配人工安全员和物理急停，不能按“无人值守自主飞行”宣传。**
